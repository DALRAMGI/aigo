# 분석 품질 개선 (보류 중)

2026-11-08 기준 상태와 다음 작업을 정리한다. 앱 디자인 작업을 먼저 하기로 해서 이 작업은 보류했다.

## 현재 상태

품질은 합격선에 미달한다. 정답은 아직 팀이 확인하지 않은 초안이고(`apps/api/eval/golden.json`의 `checked_by`가 모두 비어 있음), 표본도 작다.

| 지표 | 합격선 | 현재 (25개, 2026-11-05) |
|---|---|---|
| 충돌 시각 1초 이내 | 80% | 3/18 |
| 정답 도표 선택 | 70% | 1/6 |
| 정답 과실이 범위 안에 포함 | 70% | 0/5 |
| 사고 없는 영상에 과실 표시 | 0건 | 0/7 |
| 근거 시각 일치 | 표본 30개 이상, 90% | 미측정 |

원본 결과는 `apps/api/eval/results/`에 있다. 측정 조건은 gpt-5.5, 추론 low, 프롬프트 `2026-11-06.2`, 측정 비용 $3.35다.

## 원인

**사고 영상의 대부분을 "사고 장면 없음"으로 판단한다.** 정답이 `party`인 영상 18개 중 12개를 `none`으로 냈다. 오탐은 없지만, 충돌을 놓쳐 그 뒤 단계(도표, 과실)가 시작조차 하지 않는다.

블랙박스에는 접촉 순간이 잘 찍히지 않는다. 차가 화면 가장자리나 사각에서 스치기 때문에, 프레임만 보는 지금 방식으로는 충돌을 확인하지 못한다.

2026-11-07 운영 시험에서도 같은 영상이 전체로는 "진로변경 중 충돌", 0~15.8초로 자르면 "사고 장면 미확인"으로 나왔다.

## 이미 해 본 것 (효과 없음)

| 실험 | 결과 |
|---|---|
| 프레임 추출 간격 변경 (`exp-sampling-dev`) | 충돌 시각 1/6, 개선 없음 |
| 프롬프트 수정 (`exp-prompt-dev`) | 관여 판정은 62%로 올랐지만 충돌 시각 1/6 그대로 |
| 추론 강도 medium (`exp-effort-medium`) | 개선 없음, 최대 처리 시간 100초로 증가 |

## 다음 작업: 충돌 추정

접촉 장면이 보이지 않아도 아래 근거가 함께 나타나면 "충돌 추정"으로 판단한다. 보이는 사실만 쓴다는 원칙은 유지하고, 추정은 추정이라고 레포트에 표시한다.

- 소리: 충돌음 크기와 시각
- 화면 흔들림: 카메라 자체의 급격한 움직임
- 충돌 뒤 움직임: 상대 차의 급정지, 궤적 꺾임, 내 차 감속

작업 순서는 다음과 같다.

1. 팀이 정답 라벨을 확인한다(`checked_by` 채우기). 특히 `unsure`와 `note`에 "팀 판단 필요"가 적힌 항목.
2. 위 근거를 `apps/api/app/pipeline/`(`scan.py`, `locate.py`)에 추가한다.
3. 전체 재측정을 한다. 약 $10 정도이며, 사용자 승인 뒤 실행한다.
4. 합격선을 넘으면 README의 평가 결과를 갱신한다.

측정 명령은 `cd apps/api && uv run python -m app.evaluate --videos <폴더>`다. 다시 채점만 할 때는 `--rescore eval/results/<시각>.json`이며 비용이 들지 않는다. 영상은 저장소에 넣지 않는다(`eval/videos/`는 git 무시).

## 웹과 앱에 미치는 영향

분석은 worker에서만 돈다. 그래서 레포트 형식을 바꾸지 않으면 worker 배포만으로 웹과 앱이 함께 좋아진다.

- **레포트에 항목을 추가할 때:** 웹, 앱 화면, 앱 PDF(`apps/app/src/lib/report-html.ts`)를 함께 고친다. 앱은 새 APK가 필요하다. 이미 설치된 앱이 깨지지 않게, 기존 항목은 바꾸지 말고 추가만 한다.
- **DB를 바꿀 때:** API를 먼저 배포해 마이그레이션을 적용하고, 그 뒤 worker를 배포한다.
- **이미 끝난 분석:** 다시 분석해야 결과가 바뀐다. 결과가 어느 버전으로 만들어졌는지는 `analyses.pipeline_version`으로 구분한다.
